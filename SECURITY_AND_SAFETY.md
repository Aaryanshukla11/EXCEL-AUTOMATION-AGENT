### 3. Formula AST Sanitizer & Safe Formula Synthesis

The platform prohibits the injection of raw, unverified formula strings. All formulas generated by the **Formula Synthesizer Agent** must be parsed into an Abstract Syntax Tree (AST) by the Deterministic Execution Layer:

1. **Protocol Blacklisting**:
   - Any formula utilizing external links (e.g., `='[external.xlsx]Sheet1'!$A$1`), DDE links (`=cmd|...`), or dynamic web calls (`WEBSERVICE(...)`) is immediately rejected.
2. **Function Whitelisting**:
   - Only approved mathematical, statistical, logical, date/time, lookup, and text functions are permitted (e.g., `SUM`, `AVERAGE`, `XLOOKUP`, `INDEX`, `MATCH`, `IF`, `AND`, `OR`, `DATE`, `TEXT`).
3. **Syntax Tree Verification**:
   - The formula AST is checked to ensure all cell coordinate references remain within the valid bounding boxes of the target sheet.

### 4. Human-in-the-Loop (HITL) Policy Engine

The platform operates on a **Safety-First Escalation Hierarchy**. Cognitive decisions are classified into three operational safety tiers:

```
+-----------------------------------------------------------------------------------+
|                        HITL OPERATIONAL SAFETY TIERS                              |
+-----------------------------------------------------------------------------------+

  TIER 0: FULL AUTONOMOUS EXECUTION
  - Non-destructive inserts into empty columns/sheets.
  - Style replication and cosmetic formatting.
  - Inferred confidence >= 0.95 across all referenced entities.

  TIER 1: PASSIVE NOTIFICATION
  - Appending rows to existing tables where schema matches 100%.
  - Inferred confidence between 0.85 and 0.94 with no formula modifications.

  TIER 2: MANDATORY INTERACTIVE APPROVAL GATE (HALT & ESCALATE)
  - Inferred confidence < 0.85 on any referenced column, table, or entity.
  - Overwriting any cell containing an existing value or formula.
  - Deleting rows, columns, or sheets.
  - Introducing formulas that alter the inputs of existing calculation chains.
  - Multiple candidate targets matching the user's natural language directive.
```

#### 4.1 Human Approval Payload Specification
When a Tier 2 escalation occurs, the platform halts execution and presents an auditable approval card containing:
- **Plain-Language Summary**: Clear explanation of what the system intends to do and why.
- **Empirical Evidence**: The specific evidence used by the Semantic Inferrer to deduce the target (e.g., "Matched 'Gross Margin' to column F because 98% of values are ratios and header contains substring 'margin'").
- **Visual Delta Preview**: A side-by-side table displaying the current cell values versus the proposed new values.
- **Alternative Interpretations**: Other possible interpretations that were considered.
- **Action Buttons**: `Approve Plan`, `Reject Plan`, `Refine Instruction`.

### 5. Tamper-Evident Audit Ledger & Compliance

Every session maintains an append-only, cryptographically linked Audit Trail:
- Each audit log entry includes:
  - `timestamp`: UTC ISO-8601 timestamp.
  - `session_id`: Unique execution identifier.
  - `user_identity`: User ID or API service account.
  - `raw_prompt`: Exact user instruction.
  - `wo_ir_plan_hash`: SHA-256 hash of the generated WO-IR document.
  - `pre_state_hash`: SHA-256 of the workbook before execution.
  - `post_state_hash`: SHA-256 of the workbook after execution.
  - `hitl_approval_signature`: Digital record of human approval (if Tier 2).
  - `inverse_delta_uri`: Pointer to the reversible patch for rollback.
